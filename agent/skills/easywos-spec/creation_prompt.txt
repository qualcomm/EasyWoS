对话 2：/opsx:propose 创建 EasyWoS-Spec Skill
你的指令（完整原文）：

生成一个skill，这个skill的名字是EasyWoS-Spec，当OpenSpec被使用时，EasyWoS-Spec 技能也会被强制使用，用于帮助OpenSpec完善tasks.md的文档。
EasyWoS-Spec skill的内容如下：
背景：有一个EasyWoS工具，用于扫描需要移植的代码，并输出yaml文件，格式就和x64-to-arm64-asm-porting.yaml文件一致。
规范集合的介绍：这里定义每一个移植规范为一个spec。EasyWoS-Spec会读取一个包含所有预定义的spec的yaml文件，格式和combined-spec-summary.yaml一样，每个spec都有一个metadata字段，用来正则匹配需要移植的代码是否适合该规范来处理，如果适合，就按照该规范(spec)描述的移植方法来进行移植。
参数来源：EasyWoS工具生成的yaml文件。
执行逻辑：该Skill会解析EasyWoS传来的参数yaml文件，遍历该yaml文件里的所有porting_items。之后提取每一个porting_item的context字段，然后用规范集合里的每个规范的metadata字段对该context字段做正则匹配。如果匹配成功，这个porting_item就按照这个规范(spec)描述的移植方法来移植；如果全部都匹配失败，就交给LLM自己去尝试移植。匹配完时，应该生成一个最终匹配文件，每个porting_item都添加了一个port_spec_id字段。最后，配合OpenSpec生成tasks.md文件。
补充逻辑：有一个专家技能树(skilltree)。分两层，第一层是专家技能派遣(dispatcher)技能，只负责接收tasks.md文件的TODO命令，并将这些命令派遣给第二层的技能(skill)，这些叶子节点的skill负责真正的移植工作。专家技能树这块涉及的技能不需要去实现，你只需要指导tasks.md把porting_item传给专家技能派遣(dispatcher)技能(skill)即可。

结果： 通过 OpenSpec 创建了 proposal.md、design.md、specs（3个能力规范）、tasks.md。
